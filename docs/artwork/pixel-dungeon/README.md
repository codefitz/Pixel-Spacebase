# Pixel Dungeon easter egg artwork

Original artwork by Oleg Dolya (watabou), from [watabou/pixel-dungeon](https://github.com/watabou/pixel-dungeon).

Pinned revision: `ca458a28f053612973d5d6059dae5f6f2ca4fcb7`.

The 13 PNG files in `core/src/main/assets/pixel_dungeon/` are unchanged copies of the upstream `assets/` files. [manifest.json](manifest.json) records each source, destination and SHA-256. The upstream [GPL license](LICENSE.txt) is retained here. Sprite animation layouts were adapted from the corresponding upstream sprite classes, whose copyright is Oleg Dolya, 2012–2015, under GPL-3.0-or-later.

## Terrain

The original sewer atlas is 256×64 with 16×16 cells. `PixelDungeonLevel.tileVisual()` selects the original indices directly rather than passing through Spacebase atlas variants.

| Spacebase terrain | Original PD atlas cell |
| --- | ---: |
| Floor, wall, closed/open doors | 1, 4, 5, 6 |
| Entrance / exit | 7 / 8 |
| Grass appearance (`LIGHTEDVENT`) / tall grass (`OFFVENT`) | 2 / 15 |
| Embers / wall decoration / special floor | 9 / 12 / 14 |
| Floor decoration / locked exit / unlocked exit | 24 / 25 / 26 |
| Sign / well / statue / special statue / bookshelf / crafting | 29 / 34 / 35 / 36 / 41 / 42 |
| Water | 48–63, with edge bits in north/east/south/west order |
| Visible trap or planted mine / spent trap | 17 / 23 |
| Spacebase-only terrain without a counterpart | Original floor or documented compatible terrain fallback |

Water uses the unchanged 32×32 sewer water texture above a green opaque base. Grass remains passable, flammable Spacebase terrain. The first-floor setting is generated as nine rooms joined by a spanning tree and extra corridors; it recreates the recognisable sewer setting rather than copying one fixed upstream map.

## Hero skins

All sheets use 12×15 animation frames within armor rows, following original Pixel Dungeon's idle, run, attack, death, operate, fly and read indices. Spacebase equipment tiers select rows 0–6. Native armor/loader sprite dimensions and capabilities remain available again after return; Loader and HoverPod visits use the mapped humanoid appearance while retaining their capabilities.

| Spacebase hero | PD appearance |
| --- | --- |
| Commander | Warrior (`warrior.png`) |
| DM3000 | Mage (`mage.png`) |
| Shapeshifter | Rogue (`rogue.png`) |
| Captain | Huntress (`ranger.png`) |

Status avatars use the same class/armor mapping. Shapeshifted item forms use the mapped original item sheet, including when restored from a save.

The generated encounter uses four first-deck Xenomorphs and two Outer Colony Scouts. No enemy respawner or upstream campaign/quest logic is imported.

## Visit boundary and evidence

Artwork selection requires both a `PixelDungeonLevel` and an active side-level namespace. The visit is saved as `dungeon_<journeyId>`. Leaving creates the normal station scene and its normal terrain, hero, creature, feature and item textures. No global Assets values or item image identities are rewritten.

Java compilation and Android asset merging passed. No tests or in-game sessions were run. Appearance, equipment switching, shapeshifting, combat, item collection, save/reload and return rendering need the staged plan's in-game acceptance review.
